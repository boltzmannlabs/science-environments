# ADR: siRNA Designing Harness as a portable research environment

**Status:** Proposed for maintainer review; local technical surface implemented, scientific deployment incomplete.

## Context

The KRAS case demonstrated real transcript-wide generation and bounded deep assessment, followed by source-preserving specificity and sensitivity audits. Independent experimental validation remained blocked. Fresh literature comparison identified source-supported cores in the generated pool that did not enter the shortlist, including a palindrome-heuristic exclusion. These observations justify an auditable workflow, not a claim of superior biological designs.

## Decision

Use display name **siRNA Designing Harness** with matching `environments/sirna-designing-harness/` and `research/sirna-designing-harness/`. Provide the mandated README/spec/config/tasks/tests structure, small historical evidence summaries, an original portable skill and executable standard-library technical checks.

Do not vendor third-party predictors, weights, reference indices, raw publications, experimental datasets or credentials. Do not create a sham end-to-end generator or mark the environment biologically validated. The scientific engine remains agent-orchestrated through separately configured authorized tools. The repository CLI validates requests/evidence/contracts but does not submit models or services.

Record workflow modes DESIGN/AUDIT/SENSITIVITY/BENCHMARK, explicit mutation blocking, typed gates and independent-data eligibility. Preserve completed source artifacts; no scientific reruns to package the project. Store exact source/receipt hashes, aggregate observations and a bounded snapshot of selected original reports/result tables in `benchmark/KRAS/`, rather than full large/raw runs. Copied historical manifests/receipts are explicitly source-labelled and do not describe a complete portable copied run. Preserve previous project receipts when extending/resealing the contribution. Technical verification and historical scientific evidence have separate receipts.

## Alternatives rejected

- A documentation-only stub: insufficient to exercise reusable technical contracts.
- Copying the entire local engine and models: path-dependent, large and rights-sensitive; would falsely imply portable scientific deployment.
- Calling agreement or literature support independent validation: does not resolve checkpoint exposure, construct/context identity or specificity.
- Relaxing filters after the published Seq3 observation: outcome-driven tuning without an appropriate benchmark.

## Consequences

The project is portable and technically testable but not standalone scientific inference. In Progress is the honest lifecycle. Missing assets, rights, biological context, independent data and review remain explicit. New-host backend deployment and domain-specific extensions require separate work.

## Contribution workflow

Local feature branch `feat/sirna-designing-harness`. GitHub CLI was not authenticated; issue discovery/creation and PR submission were blocked. Local drafts exist, but issue-first governance is not claimed satisfied. Owner/reviewer assignment, commit/PR/approval/merge are pending; no remote write is performed automatically. The repository-wide license is not changed.
