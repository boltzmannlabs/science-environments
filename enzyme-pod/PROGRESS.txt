ENZYME POD - ENVIRONMENT CONTRIBUTION PROGRESS
Progress contribution. Not a completed or publicly released environment.

GOAL
Provide an enzyme variant-selection environment usable through the existing
Agent-Scientist, progressing toward the chemistry-aware enzyme-catalysis-gym.

IMPLEMENTED LOCALLY
- Fixed task/candidate input and strict ranked-selection validation.
- Restricted agent-facing actions, independent host audit and isolated execution
  tests using the existing Agent-Scientist conversation engine.
- Synthetic live-model connection check passed.
- A strict frozen-predictor host action is implemented: verified artifact hash,
  known IDs, unique-score budget and repeated/cache accounting. It reproduces
  both saved 200-candidate prediction sets exactly.
- Bounded native Agent-Scientist execution passed offline and live development
  tests. Live: 20 development candidates scored, 10 IDs submitted in 35.09 seconds,
  five model requests, 28,273 input + 833 output = 29,106 actual tokens.
- Isolation, forbidden-tool checks and original-source/account integrity passed.
  No GPU/platform submission or final-test-label access occurred.
- Existing external enzyme_workflow plugin supports workflow tracking/handoffs;
  its full integration into this controlled comparison is not yet complete.
- A five-model ESM reference has completed outside the agent. A read-only cache
  uses the same host scoring policy; all 200 predictions, exact parent/mutation
  context, 200-unique/250-request/50-hit accounting and audit checks verify.
  This adds no GPU demand or agent access to final experimental outcomes.
- Model design and specifications for all five required applications are written;
  these are not claims that the five full environments have already been built.
- External live specialist preflight now completed two proposal/critic/test rounds
  before the isolated native coordinator, using one shared model/score budget.
  With specialist: 61.06 s, 9 requests, 53,204 tokens; fresh matched base:
  33.27 s, 5 requests, 29,090 tokens. Both chose the same ordered ten IDs.
  Full prior history, actual score receipts and cache ledgers were verified.
- A portable external environment package now installs alongside the separate
  canonical benchmark package. Deterministic wheel builds, clean installation,
  synthetic CLI execution and an installed native-engine offline episode pass.
  Native runtime paths/revision are explicit operator configuration. The existing
  native SDK is reused read-only; a new independent SDK installation is untested.
- A 200-candidate native offline episode passes the shared accepted_selection/v1
  terminal policy: a host-accepted ten-ID selection ends execution without an
  unnecessary model call. Reports distinguish this from natural chat completion.
- One larger live development profile failed its 96,000 observed-token limit
  after a valid selection. Its final narrative response brought usage to 98,182.
  That failed attempt is retained, not relabeled as success. Usage accounting now
  records the response crossing a limit; the terminal-policy fix is being checked
  separately before a new development profile. No final accuracy claim follows.

CURRENT LIMITS
- The real run is a small development execution test, not an independent final
  accuracy comparison. This development split already informed baseline tuning.
- Full workflow-plugin integration, independent native-runtime provisioning,
  larger live profiling and frozen repeated scientific comparisons remain open.
  The local live specialist preflight and stronger reference are now run.
- Explicit runtime configuration removes personal paths from reusable source;
  another-machine native SDK setup and company rights review remain release gates.
- This first task is retrospective variant selection, not de novo enzyme design
  or proof of reaction activity.
