# Antibody Design Results

Scientific outputs use two complementary forms: structured task/run packages and standalone task result summaries. Each run directory corresponds to a source package under `src/<task_id>/<run_id>/` and Agent-Scientist settings under `configs/<task_id>/<run_id>.json`.

## Directory structure

```text
results/
├── README.md
├── <task_id> — Results.md
└── <task_id>/
    └── <run_id>/
        ├── run.json
        ├── report.md
        ├── candidates.csv
        ├── shortlist.csv
        ├── sequences.fasta
        ├── metrics.csv
        ├── benchmark_comparison.csv
        ├── structures/
        └── raw/
```

The tree shows the standard artifact names. Each directory contains the scientific products generated by that calculation, together with any additional descriptive output files.

| File or directory | What it provides |
| --- | --- |
| `run.json` | Compact scientific configuration: preparation, stages, tool sources, inputs, parameters, outputs and artifact links. |
| `report.md` | Performed methods, calculated findings, candidate highlights, selection criteria and links to supporting results. |
| `candidates.csv` | Candidate inventory with stable identities and recorded attributes. |
| `shortlist.csv` | Selected entries and their recorded selection information. |
| `sequences.fasta` | Candidate sequence records. |
| `metrics.csv` | Calculated candidate, model or run-level measurements. |
| `benchmark_comparison.csv` | Per-run comparison values and endpoint context. |
| `structures/` | Generated or evaluated structural models. |
| `raw/` | Native scientific products, including generated libraries, prediction archives, confidence arrays and numerical analyses. |

Read `report.md` for the findings and `run.json` for the tool inputs and settings behind them. Candidate and model identifiers connect the report to the tables, sequences and structural outputs.
