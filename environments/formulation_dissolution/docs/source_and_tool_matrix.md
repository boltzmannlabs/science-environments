Public source and software capability matrix (checked 2026-10-27 UTC)

FDA Enforcement Reports API / openFDA docs — used. FDA-origin recall listings and lot identifiers were saved as read-only JSON and imported into separate episodes; FDA reason text is not a numeric dissolution result. See data/raw/fda-res-*.json and docs/data_and_provenance.md.
FDA Dissolution Methods Database — landing page read; linked interactive FDA search returned anti-abuse page. FDA describes this as recommended bioequivalence methods for drugs lacking a USP test, not a controlled manufacturer's recalled-lot QC SOP. No ranolazine method/specification retrieved.
PubChem PUG REST — documentation URL returned a verification/challenge page; no documented response contract was verified in this session, so no request or chemical-property result is claimed. Chemical identity/descriptors, if obtained, would not supply a tablet's release profile or controlled batch composition.
RDKit — available documentation, but Python module not installed in active Python. Could calculate structure descriptors after an identity/SMILES source is verified; not a dissolution predictor on its own.
DailyMed — used the documented v2 XML SPL endpoint, https://dailymed.nlm.nih.gov/dailymed/app-support-web-services.cfm ; matched currently served SPL set ID, effective version and package NDC for each FDA case. Read-only XML in data/raw/dailymed-*.xml; import_dailymed.py created data/processed/*.dailymed.episode.json. No batch formula or QC method inferred.
PubMed — homepage and query form identified; live query served a cookies-required page, so no publication claim is based on PubMed here. Zenodo public records API was used instead to identify two CC-BY-4.0 original research articles; see public_literature_catalog.json. They are not the recalled lots.
Hugging Face Datasets — public catalog URL reachable. No applicable measured ranolazine/recalled-lot dataset was inspected/validated; do not imply a training set exists because a repository is reachable.
scikit-learn, SciPy, pandas — documentation provided; none installed in the BASE Python. SciPy and pandas were installed in an isolated scratch OpenPKFlow v2.9.0 virtual environment solely for a package-example software smoke test; scikit-learn was not installed. They are computation/analysis libraries, not sources of recalled-lot data. The standard-library local baseline remains runnable; installing packages alone does not validate a product model.
BoTorch, Optuna — documentation provided; neither installed in active Python. These are optimization libraries, not experimental measurements or approval to change a product. Leave advanced acquisition disabled until verified objectives, bounds, measured training data and matched benchmark exist.
Boltzmann connector — bundled v1.3.0 but disabled/locked until user validates a key through `/add_boltzmann`; no named scientific tool contract is exposed to the active session. Never guess a direct endpoint or bypass that access gate. This is separate from public FDA/DailyMed/Zenodo APIs called over HTTPS.

OpenPKFlow — PyPI v2.9.0 wheel and package contract inspected; installed in isolated scratch virtual environment. Its six standard dissolution fits and f1/f2 tooling need measured profile inputs. evaluation/openpkflow_probe.py fitted five models ONLY on its own bundled example, not ranolazine; output data/processed/openpkflow_package_demo.json is tagged software_demonstration_only and uncalibrated. No recalled-lot model was fit.
Open Systems Pharmacology / PK-Sim particle dissolution — public documentation at https://docs.open-systems-pharmacology.org/ consulted. No compatible OSP/PK-Sim runtime found in session; no recalled-product particle size distribution, form/solubility or case profiles available. Not run; PBPK/particle simulations would not automatically represent the product-specific quality-control method.

Scientific boundary: external research literature may support an exploratory, separately labelled model after transcription review, but it cannot reconstruct recalled Glenmark/Ajanta lot-level methods, acceptance criteria, measured profiles, batch formula, or process deviations. Keep source evidence labelled literature_reported, not measured lot QC. For verification/test output see STATUS_AND_GAPS_REPORT.md.
