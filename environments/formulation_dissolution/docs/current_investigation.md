## Scientific assessment and stopping decision

Current-product baseline: not available. Individual unit release measurements: not available. Approved Ajanta method/specification: not available. Therefore criterion deviations, improvement versus frozen baseline, confidence intervals, passing/failing QC checkpoints and root cause are not evaluable. Final status: `insufficient_data`. Fixture checks verify contracts only, not scientific performance; predictive holdout and optimization replay return `not_evaluated` for lack of eligible independent measured data. `predict` refuses to simulate the Ajanta product without an applicable verified model, candidate formula and method.

Competing hypotheses (not findings): changes in release-control material attributes; API physical state; compression/porosity; storage moisture/age; and assay or vessel/method effects. To discriminate, first recover the approved dissolution SOP and limits, original and retain-unit individual curves, qualified passing comparator lots, batch/ingredient and process records, and storage/OOS records. Stratify by method, strength, batch and interval; review unit variability and assay/system suitability before selecting a targeted controlled follow-up. A physical experiment or product change requires separate human authorization and a real verified backend, neither configured here.

## Software boundary

The CLI imports/verifies history, provides descriptive analysis and safe abstention, creates benchmark status artifacts and implements a fixture-only submitted job with idempotency. The pre-existing six specialist modules, episode state, validator, adapter registry and baseline are reused but NOT yet wired into a full closed-loop optimization coordinator for this case. No real laboratory adapter, validated commercial tablet model, independently verified patent composition, approved analytical method, source-backed specification, grouped measured holdout, scientific performance comparison A–D or validated improvement is implemented. Configure budgets/stopping and a minimum improvement rule only after obtaining controlled data; null budgets never mean unlimited. See README and `python -m cli --help`.
