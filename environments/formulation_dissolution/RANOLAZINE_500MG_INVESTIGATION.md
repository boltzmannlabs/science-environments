Ranolazine 500 mg extended-release: evidence-led investigation and optimization status
Checked 2026-10-27 UTC. Scope: Glenmark recall D-0092-2024 ONLY; Ajanta 1000 mg is a different product/event.

Research question
Can an agentic system identify formulation or process contributors to this reported dissolution failure and propose a more robust formulation? Current answer: no causal identification or validated improved formulation is possible with presently available case-specific data. The system can verify public identity, enumerate discriminating hypotheses, enforce evidence/approval gates, and demonstrate analysis software on NON-product example data. This is not a declaration that any excipient, manufacturer process or FDA method caused failure.

Data inventory and what cannot be inferred
Available: FDA public recalled product/lot identifiers, qualitative current ingredient identities, current labeled dosage-form appearance/storage, and two separate research publications indexed in data/processed/public_literature_catalog.json. The publications are NOT Glenmark lot 17230388 records. No authorized case-specific API particle-size distribution, solid-state/solubility-by-media assay, excipient weight fractions, tablet mass/hardness/porosity, batch recipe, granulation/compression/coating settings, storage exposure, approved product-specific dissolution method or acceptance specifications, failing/passing lot profiles, individual-unit release measurements, deviations, change-control records, or quantitative stability results were obtained.
FDA's publicly described dissolution-method database covers recommended generic bioequivalence methods where a USP method is absent; its linked interactive search returned an anti-abuse page. No ranolazine entry was read and no method was assigned to the recalled batch. A public research study's dissolution method is not Glenmark's approved QC SOP.

Six requested agent roles (implemented as bounded LOCAL functions; SCI delegation disabled)
Recall Research Agent: checked FDA enforcement listing, product and lot, and kept Ajanta separate.
Evidence Retrieval Agent: checked three public raw snapshots against recorded SHA-256 hashes; flagged all four unresolved case data groups.
Formulation Analysis Agent: can assess qualitative identity; actual fractions, dose/potency basis, manufacturability constraints and compatibility evidence are insufficient. No recipe was generated.
Dissolution Modeling Agent: OpenPKFlow v2.9.0 installed in isolated scratch environment and executed only against its bundled example_dissolution.csv (NOT ranolazine). Six example timepoints per example formulation; five empirical models were compared by in-sample AICc. Best on package reference example was Weibull (AICc 12.3682); best on package test example was Hixson–Crowell (AICc 16.8379). Package CLI gave example f1 12.34 and f2 57.87, also NOT ranolazine. These are software-demonstration outputs, not predictions, similarity results or metrics for this product. Source/reproducible script: evaluation/openpkflow_probe.py; output data/processed/openpkflow_package_demo.json. No independent holdout, per-vessel case profiles or calibrated uncertainty are available. Open Systems Pharmacology particle dissolution was not run: no verified API PSD, particle form/solubility, qualified model inputs, case dissolution measurements or installed PK-Sim/R runtime; a physiological particle model cannot stand in for an unverified product QC test.
Experimental Design and Bayesian Optimization Agent: withheld composition search: the original fractions, safe bounds, verified objectives, process constraints, measured responses and physical-experiment approval are missing. Proposed next step is acquisition/analysis of controlled failing and passing lots, not a physical trial. No BO objective score or recommended fraction is reported.
Independent Validation Agent: source-link auditor accepted public claims and verifier found no episode inconsistencies. This is NOT validation of a release model, formulation equivalence, product robustness or root cause. Role statuses: data/processed/D-0092-2024.investigation.json.

Hypothesis families — not findings or a ranked root-cause list
Given authorized historical records, compare polymer identity/grade/level, API particle/solid-state attributes, tablet compaction/hardness/porosity, granulation and coating, storage/moisture, and dissolution apparatus/media/sampling/analytical variation across passing/failing lots. Design discriminating checks only when controlled records establish which variables changed; do not assume the current label supplies original ingredient fractions.

Constraint/decision gates and next actions
1. Obtain authorized batch manufacturing record and product version for lot 17230388 plus passing reference lots; verify API PSD, potency, actual excipient identities/amounts/grades, tablet weight, process settings, storage/deviations.
2. Obtain authorized versioned product-specific dissolution SOP, acceptance stages/timepoints, validated assay and individual-unit failing/passing profiles. Validate provenance, time units, identities and method comparability before fitting profiles.
3. Then use OpenPKFlow to compare observed profiles and fit appropriate models; evaluate uncertainty on independent lot/replicate splits, and cross-check with a conventional baseline. If suitable inputs/model exist, assess OSP particle dissolution separately and document physiological versus QC endpoint mismatch. No automatic transfer of literature profiles to product-specific optimization.
4. Define explicit dose, tablet-weight, allowable material/process bounds, stability, manufacturability and release objectives before Bayesian optimization. Propose candidates as predictions with calibrated limits, then require authorized human-approved lab confirmation across expected material/process variation before saying “more robust.”
