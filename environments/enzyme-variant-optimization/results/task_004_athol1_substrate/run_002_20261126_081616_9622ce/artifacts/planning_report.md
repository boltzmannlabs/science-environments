## 1. Recommended stage-by-stage route (exact job names, artifacts, handoffs)

Stage 1 (parent, done by parent agent): freeze 235-aa SEQRES parent + sha256, SAH PDB, CCI input, edit mask, RUN_PLAN. Parent supplies all inputs; this pass does not re-derive them.

Stage 2 — baseline on chosen endpoint + safeguards:
- `Cat_Pred` on CSV `Seq_id,Sequences,SMILES` with parent row: `Seq_id=PARENT_3LCC`, `Sequences=<235 aa>`, `SMILES=<CCI + SAH co-substrate representation agreed by parent>`. Gives the baseline predicted kcat/Km/Ki for the parent (the chosen endpoint, §2).
- `Boltz2` with `Protein_Sequences=["<235 aa parent>"]`, `SMILES=["<SAH>","<CCI>"]` → parent ternary complex (protein+SAH+CCI) + confidence. This is the *reactant complex* baseline (not a TS model).
- `Mol_Probity` measurement_only on that parent complex → quality report.
- `Catalytic_Geometry` measurement_only on the parent complex with a user-defined reaction template (§3) → measured reaction-relevant geometry (e.g. CCI carbon···SAH sulfur distance and halide-channel geometry), reported as descriptive measurement, not a catalytic criterion.
- All four run in parallel; none depends on another's output.

Stage 3 — constrained generation, round 1:
- `Random_Controlled_Mutagenesis` with inline `seq=<parent>`, `n_samples=N1` (within ≤24 unique sequences total incl. parent), `file_format="csv"`, `indices=<zero-based protected positions>`, `mutaions_per_epoch=K` (≤8; use 1–3). Produces a CSV of complete mutant sequences. This is a *tool-based constrained generation* of whole sequences; it is not MLDE and not "LM-proposed substitutions."
- Constraint gate on the returned CSV before any downstream use: sequence length 235, standard alphabet, protected positions identical to parent, Hamming distance to parent ≤8, reject duplicates/native recoveries from the unique-variant ledger, record every draw/ID/hash/seed/settings.

Stage 4 — property screen (declare shortlist rules before seeing outputs):
- Fast filters on the *validated* sequences (no job needed): edit mask, ≤8 substitutions, no stop/nonstandard.
- `Thermal_MPNN` on a ZIP of per-candidate PDBs (first chain) → per-mutation ddG; `Netsolp` on CSV with exact `Sequences` column (`prediction_type="SU"`) → solubility+usability; `Enzymes` on CSV `Seq_id,Sequences` with `property_name=["tmPred_enzymes","enzyme_solubility","function_prediction"]` → stability/solubility/function annotations.
- Shortlist rule (declared, not fitted to results): keep variants with no high-risk stability/solubility flags relative to parent, then rank remaining by the endpoint from Stage 5 `Cat_Pred` (§2). Keep raw values separate — folding/stability/expression predictions are risk flags, never treated as activity.

Stage 5 — candidate reaction complexes with BOTH partners:
- For each shortlisted sequence (and a matched parent control), `Boltz2` with `Protein_Sequences=[candidate]`, `SMILES=["<SAH>","<CCI>"]` → per-candidate complex + confidence.
- Verify per candidate: full 235-aa sequence, SAH and CCI both present with correct chemical states/stereochemistry, atom mapping consistent, chain/component IDs as expected, quality report.
- `Mol_Probity` measurement_only on each candidate complex → per-candidate quality. `Catalytic_Geometry` measurement_only with the §3 template → per-candidate reactive geometry measurement. Assessment is accommodation + reactive geometry, not a reaction barrier.

Stage 6 — results-driven revision batch (≥1 required):
- Decision grounded in observed Stage-5 geometry/quality: e.g. if CCI carbon sits too far from SAH sulfur in the parent-like pose, or the halide-channel waters are displaced, change strategy from broad random mutagenesis to a region-focused batch (narrow `indices` to the observed pocket-lining positions from the frozen 9 Å list, keeping the nucleophile-channel residues protected or targeted as decided) and/or change `mutaions_per_epoch`. Record the observation→decision link and what changed (region/constraints/count).
- Re-run `Random_Controlled_Mutagenesis` with the revised `indices`/`mutaions_per_epoch` (round 2, the last allowed revision). Same validation gate, cumulative ledger, ≤24 unique sequences.

Stage 7 — re-evaluate revisions + combined mutations directly:
- Run `Cat_Pred` on a single CSV containing round-1 shortlist, round-2 variants, any deliberately combined mutations, and the matched PARENT row (same SMILES column for all). This is the matched-parent comparison on one common protocol; directly evaluate combined mutants rather than inferring them additively.
- `Boltz2` → structures for every round-2/combined candidate with both partners; `Mol_Probity` + `Catalytic_Geometry` measurement_only on each. Re-run the Stage-4 risk tools for any new sequence.
- Keep endpoint, geometry, quality and confidence in separate columns/tables.

Stage 8 — seal and independent evaluation:
- Freeze ≤5 candidates (no padding), with full sequences, IDs, hashes, lineage, seeds/settings and raw outputs. Parent agent delegates read-only review to enzyme-evaluator; independent common-protocol evaluation uses `Cat_Pred` (+ `Boltz2`/`Mol_Probity`/`Catalytic_Geometry` as the structure/geometry protocol) on exactly the sealed set plus matched parent.

## 2. Primary endpoint (one choice)
`Cat_Pred`, predicted kcat (and Km/Ki returned alongside). Units/sign: Cat_Pred returns predicted kcat, Km, Ki columns for each row; the contract does **not** specify units, a favorable direction, or a validated mapping to this specific enzyme/reaction, so units must be read from the returned file and never assumed (kcat convention: larger turnover is the favorable direction; Km convention: smaller is favorable — but this is general enzymology, not a Cat_Pred-documented threshold). Direction for ranking: higher predicted kcat is preferred; do not combine with docking score or geometry into a single number.

What it is: a sequence+substrate-conditioned ML prediction of steady-state kinetic parameters. What it is NOT: not a measured activity, not a reaction barrier/activation energy, not an electric-field or electronic-structure quantity, not a docking score, and not validated for AtHOL1 + ethyl iodide + SAH specifically — applicability caveat must be stated in the report. Its support is that it is the only contract-documented endpoint in the catalog that accepts sequence + substrate SMILES and returns a reaction-relevant kinetic quantity; alternatives (`kcatnet`, `kcat_km`) have documented header/run-label uncertainties.

Unavailable advanced endpoint that must remain UNRESOLVED: a SubTuner-style active-site electric-field / catalytic-field calculation for the reaction. No such endpoint exists in the 130-tool catalog; DFT tools (`Geometry_Optimization`, `Single_Point Energy`, `Reactivity_Descriptors_Combined`) are single-molecule electronic descriptors and MD e-field documentation concerns field application, not an extracted catalytic electric-field metric. Do not substitute any of them after seeing results.

## 3. Exact file preparation (contract fields and pitfalls)
- `Cat_Pred` (`file-input-contracts.v1.json`, `Cat_Pred`; module `protein-toolbox.md`): uploaded CSV with exact case-sensitive headers `Seq_id,Sequences,SMILES` (singular `Sequence` is rejected by the worker even though the credit checker lists it; lowercase `seq_id/sequences/smiles` rejected; forbidden columns `sequence`, `smile`). `Sequences` alphabet ACDEFGHIKLMNPQRSTVWY; `SMILES` validated. One SMILES per ligand entity; for a two-partner reaction encode both CCI and SAH consistently across all rows including parent. `input_path` = upload reference; no `prediction_type` field.
- `Random_Controlled_Mutagenesis` (`protein-optimization.md`): inline `seq` string (standard alphabet only, no tag if tag is outside the 235-aa SEQRES unless included consistently), `n_samples` int, `file_format="csv"`, `indices` = zero-based protected positions, `mutaions_per_epoch` int (1–109; **API typo: `mutaions_per_epoch`, not `mutations_per_epoch`**). Protected `indices` must be computed from the frozen edit mask; keep at least one mutable position.
- `Solublempnn` if used as alternative: `input_path` is a **ZIP of PDBs** with N/CA/C backbone atoms; `num_seq` is a **numeric string**; `fixed_residues` and `invert_selection` (0/1) are mode-dependent. IMPORTANT UNCERTAINTY: the authorized catalog/module documents only "Use the exact source field" for `fixed_residues` and `invert_selection` — it does **not** document the selection-string encoding or which value of `invert_selection` means "fixed vs designed." Do not guess; either run a reviewed probe or avoid this tool and use `Random_Controlled_Mutagenesis`, whose mask semantics are explicit. `model_type` enum is only `"vanilla"`.
- `Thermal_MPNN`: `zip_path` = ZIP of per-candidate PDBs (first chain used; nested directories OK, no nested ZIPs); omit `chain` (empty = first chain) and omit `model_path` (custom PT inspection unsupported; do not submit the placeholder path). Output is per-mutation ddG with Model/Dataset/position/wildtype/mutation columns; confirm residue indexing and ddG sign from the actual output.
- `Netsolp`: uploaded CSV with exact `Sequences` column (plural; FASTA not supported by platform path); `prediction_type` uppercase `S`/`U`/`SU`/`US`.
- `Enzymes`: uploaded CSV with exact `Seq_id,Sequences`; `property_name` array from the fixed enum (`pHPred`,`enzyme_solubility`,`tmPred_enzymes`,`function_prediction`,`substrate_pred`); `Sequence_ID` is not accepted. If `substrate_pred` is used, supply reviewed `SMILES` per the file contract.
- `Boltz2`: inline arrays `Protein_Sequences`, `SMILES` (one complete SMILES string per entity; unused types `[]`, never `[""]`). Supply SAH and CCI as separate ligand entities. Predictions are scheduled as pairs — inspect the returned bundle to confirm a *ternary* complex was produced, not only pairwise poses.
- `Catalytic_Geometry` (`catalytic-geometry-template.md`; `file-input-contracts.v1.json`): upload `input_path` (PDB/CIF/ZIP), `reaction_template` as an uploaded **UTF-8 JSON file ≤1 MiB** (relative storage-path string, NOT an inline object; worker overwrites `template_id`, `version`, `status`), and `template_binding` as an uploaded JSON file with exactly one key `mapping_keys` (1–1000 semantic roles; each maps to a mapping-key string or `{chain_id, residue_number, insertion_code?}`). Do NOT fabricate roles if the template has none — that is a contract mismatch to report. Candidate mapping, if used, must be JSON on the Node route (CSV was rejected HTTP 400 "Mapping file must be a .json file"). Reaction template: `reaction_state` (≤128 char), `sources` (1–100 traceable refs), `checks` (1–1000) each with unique `check_id`, `type`, `rationale`, `sources` (1–20), `evidence_level` from `direct_experimental`/`mechanistic_review`/`homolog_transfer`/`user_defined`. Bounds are USER-DEFINED geometry-preservation checks, never experimentally established catalytic criteria. Use `measurement_only` (omit `quality_thresholds`); `validation` only with explicit user-requested ranges. Build distance checks from frozen coordinates: SAH sulfur (SD, chain A residue from 3LCC numbering) ↔ electrophilic carbon of CCI, and SAH SD ↔ the modelled halide site (from the W35/W68/W198 channel); angle/Bürgi–Dunitz only if the atom triplet is defined by the mechanism. Do not invent numeric cutoffs.
- `Mol_Probity`: `input_path` one structure/ZIP; default `measurement_only` ⇒ omit `quality_thresholds` entirely (do not send all-zero frontend defaults). If ligand restraint dictionaries are needed, use the documented `ligand_manifest.json` v1/v2 bundle only with verified SMILES and bijective heavy-atom mapping; otherwise plain measurement.
- `Vina_Score_only_docking` if used only as an accommodation sanity check: requires uploaded receptor PDB `processed_pdb` + uploaded ligand `sdf_file`, numeric-string center x/y/z, `max_radius_size`, `exhaustivness` ∈ {8,16,32} as string, `upload_sdf` ∈ {"True","False"}. It scores supplied poses (no new search) and its score is NOT a reaction barrier or affinity measurement. Do not use it as the primary endpoint.

## 4. Constraint checks at every handoff
- Parent freeze: seq length ==235, sha256 matches frozen hash, protected residues from edit mask recorded zero-based for `indices`.
- Generation→screen: length==235 for every draw; standard alphabet; no substitution at protected positions; Hamming distance to parent ≤8; reject duplicates and count native recoveries separately; unique-sequence ledger ≤24 including parent; count generated draws separately from unique variants.
- Screen→complex: shortlist rule applied and recorded before endpoint values inspected; risk flags stored separately from endpoint.
- Complex→geometry: each candidate structure verified to contain BOTH SAH and CCI with correct protonation/stereochemistry/atom mapping; reactant complex (SAH+CCI) is distinct from any transition-state model; per-candidate structure and quality report exist (parent pose alone insufficient); candidate-specific chain IDs/residue numbers/filenames match template/binding/mapping.
- Revision→reevaluation: ≤2 sequence-revision rounds total; ≥1 actual results-driven revision with observation→decision link; combined mutations evaluated directly in the same `Cat_Pred` batch with matched parent.
- Seal: ≤5 candidates, no padding; each with own structure, both partners, quality report, full sequence/ID/hash/lineage/seed/settings/raw output; independent evaluation uses the same protocol on sealed set + parent.

## 5. Fallback / uncertainty list
- `Cat_Pred`: no documented units, favorable-direction mapping, or AtHOL1/ethyl iodide applicability; read actual output columns, report mismatch if requested properties absent; do not rename columns or resubmit to hide a mismatch. If the CSV header check rejects, create a reviewed header-corrected copy, never silently rewrite the original.
- `Random_Controlled_Mutagenesis`: API typo `mutaions_per_epoch`; wrong spelling fails schema validation. If output has duplicates/native recoveries, keep them in the draws ledger, not the unique-variant count.
- `Solublempnn`: `fixed_residues` semantics undocumented → treat as unresolved; prefer `Random_Controlled_Mutagenesis` unless a reviewed probe establishes the encoding. `num_seq` must be a string.
- `Boltz2`: pairwise scheduling may not yield a ternary complex, or ligand states may be wrong → inspect bundle; re-pose/verify chemistry with a contract-supported correction (reviewed SMILES/mapping) rather than silently substituting a docking tool as endpoint.
- `Catalytic_Geometry`: CSV mapping rejected on Node route → convert to reviewed JSON preserving IDs/keys/chains/residue numbers; missing real semantic roles → report contract mismatch, do not fabricate roles; measurement_only avoids invented permissive bounds; passed geometry ≠ activity.
- `Mol_Probity`: historical pending result/expired links → refresh same job status; measurement_only output has no universal pass/fail thresholds; do not apply frontend zero defaults.
- `Thermal_MPNN`: first-chain convention and residue indexing must be confirmed from actual output; custom `model_path` unsupported/omitted.
- Docking (`Vina_basic_docking`) has documented repeated worker failures; attempting it may fail and consume credits — approval and actual-status reporting required; it is not a substitute endpoint.
- Advanced SubTuner-style electric-field endpoint: unavailable and must stay explicitly unresolved; no silent swap after results.
- All submissions: accepted ≠ completed; retain job name + doc ID; poll same job; one submission per planned job; log every attempt against the ≤60 budget; ambiguous status is unknown, never a reason to resubmit.
