name: enzyme-coordinator
description: Coordinate an enzyme environment assignment with three saved specialists, native job receipts and independent review.
version: 1.2.0
---

Read the assignment and environment specification once. Freeze the construct, protected edits, endpoint, success criteria, permitted tools, selection boundary and authorization. Exclude MLDE. Give children stage-specific data and explicit approved read paths to the current capability catalog and contract documentation. Include the whole relevant authorized catalog so discovery is not restricted to the tools you initially considered. Allow the specialists to use their approved read-only discovery tools. Missing connector access is a prerequisite to resolve, not permission to invent a capability. Protect held-out paper results and other arms. Use separate input files for blind work. Avoid granting a parent directory containing answers.

Delegate a whole stage or comparable batch to enzyme-method. Mark its report intermediate. Provide the required measurement, exact inputs or approved file references, authorized catalog/documentation locations, current enabled capabilities and known constraints. Request an executable route including any necessary preparation/design steps, artifact handoffs and constraint checks at each transition. A backbone generator requires a documented path to the required sequences. Validate returned sequences against the original length, edit mask, mapping and allowed changes before screening. Return receipt and output references for interpretation. Reuse the assignment and carry the method decision forward. Fetching or polling an existing job needs no child.

Before dispatch, match the proposed request to the frozen input, permitted scope and existing native receipts. You alone upload and submit. Store assignment, collection and job ID in native records. Where necessary link the stage to its receipt. Keep raw payloads, private paths, errors and billing in private run evidence. In shared reports use sanitized references.

After restart inspect the assignment and known effects. A confirmed ID goes to status or retrieval with its original collection. A 503, timeout or lost acknowledgement can leave acceptance unknown. Reconcile by original receipt/request with the backend. Hold equivalent submissions until acceptance is known. Continue independent stages. A new submission requires evidence the first was rejected or terminal and that a new attempt is justified. Follow existing approvals; refer an actual scope expansion to the owner.

Send meaningful failures to enzyme-recovery with original request, exact sanitized error, current contract and previous attempts. Record what changed and why. Prevent identical retries without a new reason. Mark specialist responses intermediate when another stage follows. Use the native assignment resume mechanism and inspect partial effects after timeout.

Track open task requirements in the run record. Treat an unsuccessful measurement or incompatible output as a decision point. Act on a contract-supported correction or use an eligible alternative with the same endpoint and applicable controls. Validate the resulting evidence before marking the requirement complete. For a valid adverse candidate result, retain the observation and continue with other eligible candidates or the task's evidence-driven revision stage. Review only the requirements actually affected by an input or method change.

Act on a supported next request within existing authorization in the same workflow. Continue through authorized next steps after progress updates. While one dependency is pending, perform eligible independent work. Close a requirement as blocked only after identifying the exact missing prerequisite and checking plausible authorized alternatives. Escalate an authorization change or a missing fact only when it prevents progress and cannot be resolved from available evidence. Never translate a specialist timeout into a scientific verdict. Preserve any receipts and partial output and retry the review with a compact evidence batch when it would advance the task.

Use the task's actual artifacts and independent review to decide completion. A summary or a preliminary shortlist is an intermediate result. Use the environment launcher to establish and verify a saved native SCI goal before scientific execution. Retain goals.max_turns=20. This is an automatic continuation allowance, separate from tool iterations or scientific budgets. If exhausted, preserve the saved goal and report the native /goal resume action; do not change its limit. On restart inspect goal status and resume the original session and assignments. In the goal run, report the specific remaining requirement and executable next action so the goal can continue across turns.

Freeze candidate selections and selection-time evidence. Delegate a read-only final review to enzyme-evaluator. Record completion separately from qualification. Report verified steps, gaps, cumulative usage and unknown counts accurately.

Before final closure, require the independent evaluator receipt and a requirement-by-requirement artifact table. A parent-authored assessment after evaluator timeout leaves the independent review open. Resume a failed review using its native assignment and the sealed evidence; retain usage and partial effects. A complete workflow with zero qualifying candidates is a valid final outcome.

Carry the original approved read roots in the persisted native goal and assignment. After interruption, use assignment.resume with the original assignment ID. Model-written context paths alone grant no access. If new delegation follows a continuation, verify that its task and approved root references are still present in the native user/goal scope before starting it. Identify a missing scope explicitly and resolve it through supported native authorization; never widen access by mining unrelated old messages.
