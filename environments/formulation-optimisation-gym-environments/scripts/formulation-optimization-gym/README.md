Formulation optimization gym — ranolazine ER investigation

Scientific status: FDA-origin openFDA enforcement reporting identifies TWO distinct ranolazine ER dissolution-related recall listings, D-0092-2024 (Glenmark 500 mg) and D-0010-2027 (Ajanta 1000 mg). No controlled dissolution method, criteria, measured profiles, original batch formula or cause was supplied. Do not conflate the two products or interpret a public recall notice as a quantitative dissolution result. This is an investigation scaffold, not a formulation recommendation or validated predictor. Product/experiment decisions require expert review and explicit approval.

Install/run: Python >=3.10, standard library only. From repository root run `python -m unittest discover -s tests -v`, `python run.py sample`, `python run.py baseline`, `python run.py benchmark`. Benchmark without authorized measured dataset reports not_evaluated. Optionally `python -m pip install -e .` then `formulation-gym sample`. No credential needed locally.

Architecture: environment/ stores atomic episode JSON, typed actions, evidence-labelled observations and budgets. agents/ contains six bounded functions (formulation design, compatibility/stability, property prediction, experimental design, constraint critique, evidence auditing); no LLM is required. models/ contains measured-data-only nearest-mixture baseline, descriptive holdout metrics, illustrative cost-aware acquisition ranker. tools/ contains deterministic composition validation and a registry for authorized documented callables. evaluation/ contains independent verifier, zero-call conventional baseline and group-held-out benchmark. run.py orchestrates cautious triage. See docs/ for detailed contracts.

Quickstart: `python run.py sample` uses no scientific fixture and returns unknowns; `python run.py sample --state data/processed/D-0092-2024.episode.json` and the corresponding D-0010-2027 episode review FDA-sourced facts separately. Tests also use clearly labelled synthetic unit-test objects. To resume an authorized investigation, construct Episode(task), apply Action using execute, save to a private state JSON via Episode.save, then pass `python run.py sample --state /path/to/state.json`. Do not commit confidential state. `python import_fda.py --recall data/raw/fda-res-D-0092-2024.json --label data/raw/fda-spl-glenmark.json --out data/processed/D-0092-2024.episode.json` reproducibly regenerates one public episode. `verify_source` stores attestation; it is not an authenticated regulated record system.

Further public-source checks: `python import_dailymed.py --state data/processed/D-0092-2024.episode.json --xml data/raw/dailymed-glenmark.xml --out data/processed/D-0092-2024.dailymed.episode.json` creates a separate cross-checked DailyMed version of that episode. See docs/source_and_tool_matrix.md for every user-suggested data source and software library, what was actually accessed, and what remains blocked/not installed. Two Zenodo literature records are indexed in data/processed/public_literature_catalog.json but not treated as recall-lot measurements or validated model data.

Glenmark 500 mg investigation: see RANOLAZINE_500MG_INVESTIGATION.md and data/processed/D-0092-2024.investigation.json. Re-run the six bounded local roles with `python -m agents.investigation_coordinator --episode data/processed/D-0092-2024.dailymed.episode.json --raw-dir data/raw --demo data/processed/openpkflow_package_demo.json --out data/processed/D-0092-2024.investigation.json`. The optional OpenPKFlow software-only demo can be reproduced in an isolated environment using `python -m venv /path/to/venv`, `/path/to/venv/bin/python -m pip install openpkflow==2.9.0`, and `/path/to/venv/bin/python -m evaluation.openpkflow_probe --out data/processed/openpkflow_package_demo.json`. Its bundled example profiles are NOT ranolazine or QC results. Do not run product fits without verified measured profiles and methods.

Opt-in exploratory research-prototype scenario simulation (explicitly NOT the Glenmark product): see EXPLORATORY_SIMULATIONS.md, configs/exploratory_ranolazine_500.json and data/processed/ranolazine_research_scenario_results.json. This workflow evaluates paper-reported OTHER ranolazine research recipes with user-authorized unverified rate/range assumptions and OpenPKFlow first-order/Weibull forms; no measured dataset is fabricated, model is not calibrated, and scores/percentiles cannot be applied to recalled lots. Reproduce with `python -m evaluation.exploratory_scenarios --config configs/exploratory_ranolazine_500.json --out data/processed/ranolazine_research_scenario_results.json` inside an isolated venv containing `openpkflow==2.9.0`; pass `--pdf PATH` to verify the original research PDF SHA-256 before simulation. Independently check mechanical consistency with `python -m evaluation.exploratory_verifier --config configs/exploratory_ranolazine_500.json --result data/processed/ranolazine_research_scenario_results.json --out data/processed/ranolazine_research_scenario_audit.json`. Physical tests/product changes require human approval. The historical recalled-lot scientific benchmark still reads `not_evaluated`.

Tool registration: registry starts empty; the active CLI has no MCP servers and no enabled SCI web/delegation tool. Public FDA data was retrieved via terminal network calls to documented FDA endpoints; this is not a registered scientific API connector. See configs/tools.example.yaml. Supply an approved documented callable, validators, capability, version, timeouts and retry policy to Registry.register(..., approved=True). Do not infer endpoints or credentials. Handle authentication outside repository. Absent tools return tool_unavailable; model prediction cannot masquerade as measured data.

Budget/approval: configure Budget limits for actions, tool_calls, proposed_experiments and completed_experiments; each recorded measurement needs approved source, approval ID, confirmatory identifier and matching source-linked measured values. No method executes physical experiments, regulated updates, purchases or production changes. Tool log stores request ID, time, tool/version, status and sanitized errors; raw scientific outputs can be preserved in episode predictions, but external data stewardship remains the user's responsibility.

Benchmark: input JSON list of source-linked measured rows with target, unit, composition fractions and group_id, plus `--materials X Y --unit UNIT`. Use `python run.py benchmark --dataset /approved/rows.json --materials X Y --unit UNIT`. Split by pre-curated group_id to avoid replicate leakage; freeze and audit grouping before publication. No numerical targets, excipient bounds or validated performance supplied. For A/B/C/D matched comparison supply authorized same-task cases, equal budgets, direct-tool/specialist runs and appropriate holdouts; the local harness does not pretend those missing arms ran.

Extending: add a specialist with typed input/output and permissions, require verifiable incremental benefit over direct tools; add tool contracts by explicit review and test success/auth/timeout/malformed responses. Run independent verifier and evidence auditor before reporting. Unresolved: controlled method/specification, lot-level dissolution results, batch formula/process, restricted source access permissions, calibrated models and approval for experiments.
